## 面经里反复出现的问法

### 框架与机制

1. 你实际跑过 vLLM / SGLang 吗？各自的核心模块是什么？
2. PagedAttention 和 Continuous Batching 分别解决什么问题？不要混在一起答。
3. SGLang 的 RadixAttention 和 vLLM 的 Prefix Caching 是什么关系？
4. Prefill 和 Decode 的瓶颈为什么相反？怎么用 profiling 证明？
5. 单请求的 KV Cache 显存怎么算？batch 放大后怎么变？
6. KV Cache 卸载到 CPU 或远端，什么时候划算？
7. vLLM 的请求从 HTTP 到 GPU 再到流式返回，经过哪些模块？
8. 单机多卡 TP/PP 怎么切？通信发生在哪里？
9. 为什么 decode 阶段 MFU 很低？怎么提升？
10. HiCache 把 KV 扩到主机内存/远端存储，收益和代价是什么？
11. MLA 与 MHA/GQA 有什么区别？对推理引擎有什么影响？

### 线上服务与流式

12. 推理服务的限流和兜底怎么做？
13. 推理时延怎么优化？先从哪一层查？
14. 流式输出怎么实现？背压怎么处理？
15. 流式过程中网络中断、前端重连，后端如何恢复上下文继续输出？
16. 用户点“停止生成”后，后端如何立即终止推理并释放资源？
17. 多轮对话 + 流式输出，如何保证消息不乱序、上下文不丢？
18. Java/Go 后端 + Python 模型服务，跨服务流式透传怎么做？
19. 流式返回如何精准统计 token 消耗用于计费？
20. 流式输出中如何实时截断敏感内容？

### 容量、成本与工程判断

21. 如何度量推理系统？TTFT、TPOT、ITL、goodput 各是什么？
22. 固定并发压测和固定到达率压测，为什么结论不同？
23. 如何估算服务容量与每百万 token 成本？
24. 模型/引擎不停服升级，怎么保证旧请求不受影响？
25. 长上下文（百万 token）推理的主要挑战是什么？
26. 上下文窗口的本质是什么？为什么标称长度用到六七成就开始下降？
27. 上下文压缩有哪些方法？
28. 优先级、抢占与多租户公平性怎么设计？
29. GPU 池化：MIG、MPS、时间切片分别隔离什么？
30. 国产/异构算力（如昇腾）适配的难点在哪里？

## 值得保留的追问方式

- “为什么？”之后继续问“什么条件下不成立？”
- “怎么优化？”之后继续问“代价是什么？怎么验证没有负优化？”
- “线上出问题怎么查？”之后继续问“指标、日志、trace 分别能证明什么？”
- “框架 A 比 B 快吗？”之后继续问“模型、版本、并发、输入输出分布固定了吗？”

这类递进追问比背结论更接近面试现场，题库里的 `followUps` 和“易错点与追问”页就是按这个思路写的。
